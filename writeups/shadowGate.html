Hacksmarter Labs Walkthrough

ShadowGate

August 6, 2026 • Easy • Target IP: 10.0.22.87

Summary: Machine starts with anonymous enumeration and finding users list, and finding an asrep-roastable user. This user is discovered to have GenericWrite relation over another user, who leads us to ESC8 exploit.

Attack Chain

  • Asrep-roasting (User 1): anonymous user enumeration -> asrep-roastable user enum -> asrep-roasted Offline Crack
  • Lateral Movement (User 2): Insecure ACL -> GenericWrite Abuse (Shadow Credentials)
  • Domain Compromise (Administrator): AD CS Misconfiguration -> ESC8 Certificate petitpotam and ntlm coersion

This tells us, we have an http-related ESC8 vulnerability at our hands. This was my first time coming scross ESC8. I found an amazing article by hacktricks here, which explains the vuln and shows how we can exploit it.

Basically, with ESC8, we can coerce the DC to authenticate any user, while relaying this to the certfnsh.asp. We hence capture the certificate of authentication that the DC signed, to perform privileged operations, such as DCSync. Feel free to go through the article, or follow along.

Remidiations

1. External Recon and Asrep Remediation
  • Disable Null Sessions: Restrict anonymous access to SMB shares by setting RestrictAnonymous to 1 or 2 in the Windows registry.
  • Enforce Pre-Authentication: Ensure the "Do not require Kerberos preauthentication" attribute is unchecked for all user accounts in Active Directory.
  • Rotate Service Passwords: Enforce strong, complex password policies (minimum 16+ characters) so that any accidentally exposed AS-REP hashes cannot be cracked offline.
2. ACL & Object Control Remediation (GenericWrite)
  • Restrict Key Credential Creation: Limit who can modify the msDS-KeyCredentialLink attribute on user objects.
  • Audit Shadow Credentials: Monitor for event IDs associated with public key changes on user objects (such as Directory Service Changes).
  • Clean Up Insecure ACLs: Regularly run BloodHound to find and remove unintended direct write permissions over high-value accounts.
3. AD CS ESC8 Remediation
  • Disable HTTP Enrollment: If not required, completely uninstall or disable the Certification Authority Web Enrollment (/certsrv/) service.
  • Enforce HTTPS and EPA: If the web endpoint is necessary, force HTTPS and enable Extended Protection for Authentication (EPA) alongside IIS Request Filtering to block NTLM relaying.
  • Disable NTLM on the CA: Disable NTLM authentication entirely on the AD CS servers, forcing the use of Kerberos.
  • Patch Coercion Vectors: Keep Domain Controllers fully updated to mitigate known RPC/SMB coercion techniques (like PetitPotam, DFSCoerce, or ShadowCoerce).
