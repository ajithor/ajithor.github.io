Hacksmarter Labs Walkthrough

Arakasa

August 5, 2026 • Easy • Target IP: 10.1.110.168

Summary: Machine starts with assumed breach user, who finds a kerberoastable user. This user has a genericAll over another user, who, in turn hash GenericWrite over another. This user is capable of enrolling in an ESC1 vulnerable template, to impersonate administrator.

Attack Chain

  • Lateral Movement (User 2): Assumed breach creds -> Service Account SPN Enumeration -> Kerberoasting Offline Crack
  • Lateral Movement (User 3): Insecure ACL -> GenericAll Abuse (Targeted Password Reset)
  • Lateral Movement (User 4): Insecure ACL -> GenericWrite Abuse (Shadow Credentials)
  • Domain Compromise (Administrator): AD CS Misconfiguration -> ESC1 Certificate Enrollment with SAN Impersonation to LDAP shell -> add user to Domain Admins group

So, we reach the end of outbound controls on bloodhound, and notice the DCOM group. This usually means, if there's a Certificate server running, there's chances of the templates being vulnerable. To test this, we use certipy-ad find option.
We see that, it finds an ESC1 vulnerable template (which is essentially an Identity theft attack), called AI_Takeover, enrollable by an account we control, soulkiller.svc.
So we request the template, while impersonating Administrator.hacksmarter.local, to get the admin's certificate and private key, so that we can then login as the admin.

vaadata has a good article here about vulnerable templates and exploiting them, a good read.

With the admin's .pfx, we try to get a direct shell, but it fails. So we now have to resort to an ldap shell. Ldap shells, while not a shell to the machine itself, gives us a few options, one of which is adding a new users, and customizing their localgroups. Which means, as domain admins, we can add a new user, and make them the admins.

Remidiations

1. Kerberoasting Remediation
  • Strong Passwords: Enforce a minimum 16-character length for service accounts.
  • Managed Accounts: Migrate traditional user accounts running services to Group Managed Service Accounts (gMSAs), which rotate passwords automatically.
  • AES Encryption: Ensure service accounts use AES-128 or AES-256 instead of weak RC4 encryption.
2. ACL & Object Control Remediation (GenericAll / GenericWrite)
  • Principle of Least Privilege: Audit Active Directory object permissions using tools like BloodHound to find unintended access control lists (ACLs).
  • Remove Direct Assignments: Remove direct user-to-user permissions.
  • Tiered Administration: Implement a Tiered Administration Model (Tier 0/1/2) so standard user accounts cannot possess administrative control over other accounts.
3. AD CS ESC1 Remediation
  • Disable SAN Enrollment: Uncheck the "Supply in the request" option on the certificate template's Subject Name tab.
  • Require Approval: Enable the "CA administrator approval" setting to prevent automatic issuance.
  • Restrict Enrollment: Limit enrollment permissions strictly to specific, required security groups rather than Authenticated Users.
