Security Audit - Offensive Go Tooling Suite

gosec • trivy • govulncheck

Author: Ajith G Nayak
Date: November 2026
Repos Audited: egress_whisperer, c2ne, callnc2(partial)
Tools: gosec, CodeQL(SAST) | trivy, govulncheck (SCA)
Pipeline: Github Actions, triggered on push to master, and on local clone.

Background

This audit covers three Go-based offensive security tools built as personal research projects:

  • egress_whisperer - pre-C2 egress testing framework; identifies which port/protocol combinations survive firewall and DPI inspection
  • c2ne - covert C2 over music-streaming traffic with dual exfiltration channels (scrobble POST and file upload)
  • callnC2 - covert C2 tunneling AES-GCM encrypted commands through bit-plane-encoded audio over HTTP/2

The goal was to integrate automated SAST and SCA scanning into CI/CD, triage all findings against the actual threat model of each tool, and document remediation decisions.

Methodology

SAST and SCA were run via GitHub Actions on every push to master. Four tools were used deliberately because they cover different layers and have different false positive profiles:

Tool Category Checks
gosec SAST Go-specific security anti-patterns via AST and SSA analysis
CodeQL SAST Deep dataflow analysis via GitHub's query engine
Trivy SCA go.mod dependency manifest scan against CVE databases
govulncheck SCA Dependency scan with call graph confirmation

Pre-Methodology Note - Trivy vs govulncheck

Trivy flags every CVE present in go.mod regardless of whether the vulnerable code path is actually reachable. govulncheck traces the actual call graph and only flags what your code genuinely calls. Where the two disagreed, govulncheck was treated as authoritative. This distinction was responsible for dismissing the majority of High severity findings in this audit - 11 golang.org/x/crypto/ssh CVEs appeared in Trivy across all repos but were absent from govulncheck output because none of these tools use SSH.

Initial analysis failure

The first gosec run on egress_whisperer returned near-zero findings despite the tool reporting it ran. Investigation revealed gosec was skipping its SSA-based dataflow checks because dependencies were not resolved before analysis. The workflow was missing a setup-go and go mod download step prior to the gosec invocation. After fixing this, gosec's finding count increased significantly, confirming the original clean result was a false negative, not a true clean pass.

Module Layout issue

Both egress_whisperer and c2ne had client.go and server.go in the same directory, both declaring package main with their own main() function. This caused go build ./... to fail with symbol redeclaration errors, which in turn caused CodeQL's autobuild to produce incomplete analysis. Both repos were restructured into cmd/client and cmd/server subdirectories. For c2ne, shared code (aes-gcm_engine.go, wav_heaer_helper.go) was moved into internal/crypto and internal/audio packages respectively.

Lessons and Notes

govulncheck vs Trivy:

The most practically useful decision in this audit was running govulncheck alongside Trivy. Trivy reported 43+ findings per repo. govulncheck reduced the confirmed actionable list to under 20 across all repos. Without call graph confirmation, the SSH CVE noise would have obscured the genuinely exploitable compress and stdlib findings.

False negatives are worse than false positives:

The initial gosec run looked clean and wasn't. A scan that silently skips half its analysis because dependencies aren't resolved is more dangerous than one that reports too much, because it creates false confidence. Diagnosing and fixing the SSA analysis failure was more valuable than any individual finding it subsequently uncovered.

Threat model drives triage:

Several Error-severity findings (Slowloris protection, subprocess execution, network binding) were dismissed not because they are invalid in general, but because they describe risks that do not apply to operator-controlled, single-use, lab-environment tools. Applying production web server hardening rules to a C2 implant is a category error.
